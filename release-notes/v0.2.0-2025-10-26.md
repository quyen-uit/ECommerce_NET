# Release Notes

## v0.2.0 — 2025-10-26

This release focuses on security hardening, consistent pagination, and correctness fixes across services and specifications. It also standardizes error responses and aligns configuration for SPA-origin validation.

### Security
- Removed hard-coded Stripe webhook secret from `PaymentController`.
- Added `StripeSettings:WebhookSecret` in config. Stripe webhook now uses configuration.
- Unified error payloads from custom middlewares to use the API response envelope.
- Reduced sensitive error detail in production 500 responses; detailed messages only in Development.

Breaking: You must configure the following secrets (via environment variables or user-secrets in production):
- `StripeSettings:SecretKey`
- `StripeSettings:WebhookSecret`
- `Token:Key` (JWT signing key)

### Pagination and Specifications
- Fixed paginated endpoints to count total records without paging by introducing non-paged specs for counts.
- Product filters corrected to use entity fields for booleans (IsNew/IsTrending/IsActive) and to filter by related names properly.
- Product SKU listing now returns `Pagination<ProductSkuDto>`; spec adds pagination and sorting for search.

Endpoints affected:
- Products, Categories, Colors, Price Adjustments (accurate total counts)
- Product SKUs (pagination contract updated)

### Service Logic Fixes
- Price Adjustment updates now correctly synchronize nested `PriceAdjustmentItems` (remove missing, update existing, add new) using tracked entities.

### Middleware and Config
- `SpaOriginValidationMiddleware` and `RefreshRateLimitMiddleware` now respond with the standard error envelope.
- Default SPA origin aligned to `https://localhost:4200` (can override with `Spa:Origin`).

### API Contracts
- `IOrderService.CreateOrderAsync` return type changed to non-nullable `Task<Order>` to match behavior (exceptions on failure) and remove nullability warnings.
- `IProductSkuService.GetAllProductSkusAsync` now returns `Task<Pagination<ProductSkuDto>>`.

### Cleanup
- Removed unused `ApiError` class.

### Upgrade Notes
1. Set secrets and sensitive values using environment variables or user-secrets; leave placeholders in `appsettings.json`.
2. If you consume the Product SKU search endpoint, update client code to expect a `Pagination<ProductSkuDto>` payload.
3. If you rely on detailed server error messages in production, note that generic messages are now returned with details only in Development (logs contain full details).

### Internal References
- PaymentController: `src/API/Controllers/PaymentController.cs`
- Middleware: `src/API/Middlewares/*`
- Services updated: `ProductService`, `CategoryService`, `ColorService`, `ProductSkuService`, `PriceAdjustmentService`
- Specifications updated: `ProductWithTypesAndBrandsSpecification`, `CategorySpecification`, `ColorSpecification`, `ProductSkuWithColorAndSizeSpecification`, `PriceAdjustmentSpecification`
